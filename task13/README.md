# Лабораторные работы №12–13 — Zen-Money на Next.js

Приложение для учёта финансов на Next.js: список операций, добавление, сводка 
и страница детального просмотра одной операции. Также включает деплой на Vercel.

## Запуск

Открой **два окна CMD** и выполни по очереди:

**Окно 1 — сервер данных (не закрывать):**

```
cd /d D:\web-course-2026\task13
json-server --watch db.json --port 3001
```

**Окно 2 — Next.js (не закрывать):**

```
cd /d D:\web-course-2026\task13
npm run dev
```

Открой в браузере: http://localhost:3000

## Структура

- `app/layout.js` — общий layout с навигацией и летающими смайликами
- `app/page.js` — главная, список всех операций
- `app/add/page.js` — форма добавления операции
- `app/stats/page.js` — сводка (доходы, расходы, баланс)
- `app/transaction/[id]/page.js` — детальный просмотр одной операции
- `app/globals.css` — стили
- `lib/api.js` — работа с json-server через fetch
- `db.json` — данные

## Страницы (файловый роутинг)

| URL | Файл | Что показывает |
|---|---|---|
| `/` | `app/page.js` | Список всех операций |
| `/add` | `app/add/page.js` | Форма новой операции |
| `/stats` | `app/stats/page.js` | Сводка: доходы, расходы, баланс |
| `/transaction/:id` | `app/transaction/[id]/page.js` | Детали одной операции |

## Динамический роут

Страница `app/transaction/[id]/page.js` использует квадратные скобки в имени папки — 
это специальный синтаксис Next.js. Когда пользователь открывает `/transaction/5`, 
значение `5` попадает в параметр `id`, который можно получить через хук `useParams()`. 
Дальше страница по этому `id` запрашивает конкретную операцию у сервера 
(`GET /transactions/5`).

Клик по карточке в списке ведёт на эту страницу через `<Link href={/transaction/${t.id}}>`.

## CSR, SSR и SSG — в чём разница

Это три подхода к тому, **где и когда** формируется HTML страницы.

**CSR (Client-Side Rendering) — рендер на клиенте.**
Сервер отдаёт пустой HTML и большой JS-файл. Браузер сам скачивает данные через 
`fetch` и рисует страницу. Плюс: интерактивность сразу, дешевле сервер. Минус: 
первая загрузка медленнее, SEO хуже (поисковик может увидеть пустую страницу). 
В нашем проекте **все страницы — клиентские** (`'use client'`), потому что данные 
живут в `json-server` на нашем компьютере, а не на сервере Vercel. Клиент сам 
делает запросы к API после того, как страница загрузилась.

**SSR (Server-Side Rendering) — рендер на сервере при каждом запросе.**
Пользователь заходит на страницу → сервер идёт в базу, собирает готовый HTML 
с данными → отдаёт браузеру → браузер «оживляет» его (гидратация). Плюс: 
быстрая первая отрисовка, отличное SEO, всегда свежие данные. Минус: нагрузка на 
сервер. **В нашем проекте SSR был бы уместен для страницы `/stats`**, если бы 
данные приходили не с локального `json-server`, а с настоящего API — тогда сервер 
сам бы считал суммы и отдавал готовый HTML с цифрами.

**SSG (Static Site Generation) — генерация на этапе сборки.**
Страница собирается **один раз** при деплое и отдаётся как статический HTML всем 
пользователям. Плюс: молниеносная загрузка, копеечный хостинг. Минус: данные 
устаревают, пока не пересоберёшь проект. **В нашем проекте SSG подошёл бы для 
страницы «О проекте»** — она не зависит от базы и одинакова для всех. Или для 
списка категорий (Еда, Зарплата и т.д.), которые меняются редко.

**Итого по нашему проекту:**
- Все страницы — **CSR** (из-за `'use client'` и локального `json-server`).
- **SSR** был бы уместен для `/stats` — чтобы цифры приходили уже в HTML.
- **SSG** был бы уместен для статических страниц (например, «О проекте»).

## Деплой на Vercel

Проект задеплоен на **Vercel**: [ссылка на деплой]

**Важно:** Vercel не может обратиться к `http://localhost:3001`, потому что 
`json-server` работает только на моём компьютере. Поэтому **на задеплоенной 
версии данных нет** — это ожидаемое поведение для этой лабораторной. Чтобы 
приложение работало полностью, нужно:
1. Запустить `json-server` локально на порту 3001.
2. Открыть локальную версию (`npm run dev`) — она обратится к серверу и покажет данные.

Для полноценной работы в интернете нужен настоящий API (например, MongoDB Atlas 
или Supabase) — но это выходит за рамки данной лабораторной.

## Возможности

- Просмотр списка операций
- Добавление операции (сумма, тип, категория, дата, комментарий)
- Удаление операции
- **Детальный просмотр одной операции** по клику на карточку
- Сводка: доходы, расходы, баланс
- Навигация через `next/link` (без перезагрузки страницы)

## Технические особенности

- Файловый роутинг App Router (папки = URL-пути)
- Динамический роут `[id]` + хук `useParams()`
- Клиентские компоненты через `'use client'`
- Все запросы через `fetch` с `async/await` внутри `useEffect`
- Переменная окружения `NEXT_PUBLIC_API_URL` для адреса API (по умолчанию `http://localhost:3001`)
