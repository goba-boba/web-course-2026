## Структура

- `src/App.jsx` — главный компонент
- `src/utils/todos.js` — чистая логика фильтрации и сортировки (тестируется отдельно)
- `src/utils/todos.test.js` — юнит-тесты логики (6 тестов)
- `src/components/TodoForm.jsx` — форма добавления
- `src/components/TodoForm.test.jsx` — тесты формы (3 теста)
- `src/components/TodoItem.jsx` — одна задача
- `src/components/TodoItem.test.jsx` — тесты задачи (2 теста)
- `src/components/TodoList.jsx` — список
- `src/components/Filters.jsx` — фильтры
- `src/components/SortSelect.jsx` — сортировка
- `src/components/Stats.jsx` — счётчики
- `src/setupTests.js` — конфигурация тестов

## Какие сценарии покрыты

**Логика (`todos.test.js`):**
- ✅ Обычный случай: фильтр `all` возвращает все задачи
- ✅ Краевой случай: пустой массив
- ✅ Случай без совпадений: фильтр `completed`, когда выполненных нет
- ✅ Некорректный фильтр — функция не ломается, возвращает все
- ✅ Сортировка по алфавиту (А→Я)
- ✅ Сортировка не мутирует исходный массив

**Компонент `TodoForm`:**
- ✅ Рендерит поле ввода и кнопку «Добавить»
- ✅ При вводе и клике вызывает `onAdd` с правильным аргументом
- ✅ Не вызывает `onAdd` при пустом поле

**Компонент `TodoItem`:**
- ✅ Рендерит текст задачи
- ✅ При клике на «Удалить» вызывает `onDelete` с правильным `id`

## Что сознательно не покрыто тестами

- **Интеграция с localStorage** — это побочный эффект, для его тестирования нужно мокать 
  `localStorage` и таймеры. Это выходит за рамки минимального набора, требуемого в задании.
- **Компоненты `Filters` и `SortSelect`** — они просто вызывают переданные коллбэки. 
  Тестировать их — дублировать уже покрытые сценарии (`TodoForm` и `TodoItem` уже показывают 
  работу с коллбэками и событиями).
- **Компонент `Stats`** — простая арифметика, легко проверяется визуально, критичной логики нет.

Покрытие функциональности: ~70% (вся бизнес-логика + ключевые компоненты с событиями).

## Технические особенности

- `Vitest` как тестовый раннер (интеграция с Vite из коробки)
- `jsdom` — эмулирует браузерную среду для тестов
- `@testing-library/react` — рендер компонентов и симуляция событий
- `@testing-library/jest-dom` — дополнительные матчеры (`toBeInTheDocument` и др.)
- `vi.fn()` — мок-функции для проверки вызовов коллбэков
